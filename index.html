01 — Concepto

¿Qué es el NFC?

Una tecnología de comunicación inalámbrica de muy corto alcance que permite intercambiar datos entre dos dispositivos con solo acercarlos.

13.56MHz Frecuencia de radio estándar (banda HF, ISM)
≤ 4cm Alcance efectivo: requiere proximidad física deliberada
424kbps Velocidad típica (máx. 848 kbps en ISO 14443)
<0.1seg Tiempo de establecimiento del enlace RF

Es una evolución del RFID. La diferencia clave: el NFC permite comunicación bidireccional y un dispositivo puede actuar simultáneamente como lector o como etiqueta (HCE).

02 — Historia

De RFID al bolsillo

El NFC es la evolución de décadas de investigación en radiofrecuencia de campo cercano y tarjetas inteligentes sin contacto.

1983

RFID patentado — Charles Walton obtiene la primera patente US4384288 para un sistema de acceso sin contacto por inducción magnética.

1994

ISO 14443 — Se publica el estándar para tarjetas de proximidad (PICC) que define Type A y Type B. Base física del NFC moderno.

2002

Nace el estándar NFC — Sony y Philips (NXP) crean conjuntamente la especificación, fusionando FeliCa con ISO 14443 en una sola interfaz.

2004

NFC Forum — Nokia, Sony y Philips fundan el consorcio. Publican NDEF, RTD y las especificaciones de Tag Types 1–4.

2010

Samsung Nexus S — Primer smartphone Android con chip NFC integrado. Google habilita la API NFC pública en Android 2.3 Gingerbread.

2011

Google Wallet — Primer monedero digital NFC masivo. Introduce HCE (Host Card Emulation) en Android 4.4 KitKat.

2014

Apple Pay (iPhone 6) — Apple integra NFC pero solo para pagos vía Secure Element. El acceso general a apps de terceros queda bloqueado.

2019

CoreNFC abierto — iOS 13 permite lectura de tags ISO 15693 y escritura NDEF desde apps de terceros. Entitlement obligatorio.

2020

Web NFC API — Chrome 89 para Android implementa NDEFReader, llevando NFC al navegador sin instalar app nativa.

2023

ICAO 9303 — Los pasaportes electrónicos globales usan NFC con BAC/PACE y cifrado AES-128 para leer el chip biométrico de forma segura.

03 — Funcionamiento interno

La física detrás del "tap"

El NFC no transmite ondas de radio "al aire": funciona por acoplamiento inductivo mutuo entre bobinas.

  1. 1
    Campo magnético oscilante

    El lector hace circular corriente alterna por su antena (bobina L) y genera un campo magnético a 13.56 MHz. Potencia típica: 200 mW.

  2. 2
    Inducción electromagnética

    Al acercar la etiqueta, ese campo induce una FEM en su bobina receptora (Ley de Faraday). Así la etiqueta pasiva se energiza sin batería; obtiene ~5–15 mW.

  3. 3
    Modulación de carga (Load Modulation)

    La etiqueta responde variando la impedancia de su antena a una subportadora de 847.5 kHz. El lector detecta esos cambios en su propia tensión y los decodifica como bits.

04 — Técnica profunda

Stack de protocolos

NFC no es un solo estándar: es una pila de normas ISO que operan en capas bien definidas.

ISO 14443 Tarjetas de proximidad. Type A: ASK 100% / Miller modificado / anticolisión bitwise. Type B: ASK 10% / NRZ-L / anticolisión por slot. Hasta 848 kbps.
ISO 18092 NFCIP-1. Modo Peer-to-Peer activo y pasivo. Velocidades: 106, 212, 424 kbps. Define el handshake ATR_REQ / ATR_RES.
ISO 15693 Tarjetas de vecindad pasivas. Alcance hasta 1 m. Modulación ASK 10%/100%. Anticolisión RFID por ranura (16 slots). Tag Type 5.
ISO 7816-4 Capa de aplicación APDU. Comando: CLA INS P1 P2 [Lc Data] [Le]. Respuesta: Data SW1 SW2. Usado en DESFire, HCE y pasaportes.
Modulaciones: Type A — ASK 100% · Miller · anticolisión bitwise (UID 4/7/10 bytes) · Type B — ASK 10% · NRZ-L · anticolisión por N slots
Aplicación NDEF · Smart Poster · APDU ISO 7816
NDEF / RTD NFC Forum — Message · Record · Payload
ISO-DEP ISO 14443-4 — Activación T=CL · I-Block · R-Block
MAC / Anti-colisión ISO 14443-3 — UID · SAK · ATQA · CRC_A/B
PHY 13.56 MHz · ASK · ISO 14443-2 · Miller / NRZ-L
T1 · Topaz T2 · Ultralight T3 · FeliCa T4 · DESFire T5 · ISO15693

05 — Anatomía

¿Qué hay dentro?

Una etiqueta NFC es asombrosamente simple: solo dos piezas y ninguna batería.

⌾

Antena de bobina

Un fino hilo de cobre o aluminio enrollado en espiral (tipicamente 3–6 vueltas). Capta el campo del lector, lo convierte en energía y actúa como canal de comunicación bidireccional.

▣

Microchip (IC)

Almacena los datos en EEPROM (96 B–32 KB según tipo), gestiona el protocolo y ejecuta la lógica de anticolisión. En etiquetas pasivas toda su energía proviene de la inducción.

Pasivo vs. Activo. La etiqueta (tarjeta, sticker, implante) es pasiva: sin fuente propia. El teléfono es activo: alimenta al lector NFC y — cuando hace falta — energiza a la etiqueta por inducción. El teléfono siempre inicia la comunicación y controla el campo RF.

06 — Modos de operación

Tres formas de usar el NFC

Haz clic en cada modo para ver cómo se comporta el dispositivo.

📱 🏷️

Lectura / Escritura

El teléfono actúa como lector PCD (Proximity Coupling Device) y la etiqueta como PICC (Proximity Integrated Circuit Card). Lee o graba datos en tags pasivos. Caso más común: posters inteligentes, tarjetas de información, inventario.

📱 📱

Peer-to-Peer (P2P / NFCIP-1)

Dos dispositivos activos intercambian datos bajo ISO 18092. El protocolo LLCP (Logical Link Control) proporciona control de flujo. Usado para intercambiar contactos, URLs, o iniciar emparejamiento Bluetooth/Wi-Fi.

📱 🖥️

Emulación de tarjeta (HCE)

El teléfono simula ser una tarjeta sin contacto ante un terminal externo. Host Card Emulation (Android 4.4+) gestiona los APDU commands en software. El Secure Element (SE) se usa para mayor seguridad en pagos.

07 — Estructura de datos

El formato NDEF

NDEF (NFC Data Exchange Format) es el "idioma" estándar del NFC Forum. Un mensaje NDEF agrupa uno o varios registros concatenados.

  • TNF — Type Name Format: indica la familia del contenido (Well-Known, MIME, External…).
  • Type — tipo concreto del registro, p. ej. U (URI), T (Text), Sp (Smart Poster).
  • ID — identificador opcional del registro (campo variable, presente si IL=1).
  • Payload — los datos reales. Longitud en 1 byte (SR) o 4 bytes (registro largo).

09 — Flutter / Dart

Librerías y Permisos

Para usar NFC en Flutter se necesita un plugin que envuelva el Platform Channel hacia Android (NfcAdapter) e iOS (CoreNFC).

Recomendado nfc_manager ^3.3.0

API unificada Android + iOS. Soporte NDEF, ISO-DEP, MiFare, FeliCa. Stream continuo. Mantenida activamente en pub.dev.

Alternativa flutter_nfc_kit ^3.5.0

Mayor control de bajo nivel. Expone APDU raw commands y anticolisión directa. Ideal para tarjetas DESFire/MIFARE Classic.

Alternativa nfc_in_flutter ^2.x

API simplificada basada en Stream. Solo lectura NDEF básica. Ideal para proyectos simples sin escritura ni APDU.

AndroidManifest.xml + pubspec.yaml
# pubspec.yaml
dependencies:
  nfc_manager: ^3.3.0

<!-- AndroidManifest.xml -->
<uses-permission android:name="android.permission.NFC" />
<uses-feature    android:name="android.hardware.nfc"
                 android:required="true" />
<!-- En la <activity> para captura foreground -->
<intent-filter>
  <action android:name="android.nfc.action.NDEF_DISCOVERED"/>
  <action android:name="android.nfc.action.TAG_DISCOVERED"/>
</intent-filter>
<!-- minSdkVersion recomendado: 19 (Android 4.4 KitKat) -->

10 — Arquitectura

Clean Architecture + Platform Channel

La estructura recomendada separa responsabilidades en capas y utiliza un Stream<NfcTag> para reaccionar en tiempo real a cada tag detectado.

Presentation Layer Flutter Widgets · BLoC / Riverpod · StreamBuilder
↓ UseCase call  |  ↑ NfcState emitido
Domain Layer ReadTagUseCase · WriteTagUseCase · NfcRepository (abstract)
↓ Stream<NfcTag>  |  ↑ NdefMessage
Data Layer NfcRepositoryImpl → NfcService (MethodChannel wrapper)
↓ startSession()  |  ↑ onDiscovered callback
Plugin: nfc_manager NfcManager.instance · Platform Channel · dart:ffi
Android NfcAdapter · enableForegroundDispatch · NdefMessage · IsoDep · MifareClassic
VS
iOS NFCNDEFReaderSession · NFCTagReaderSession · CoreNFC · Secure Element
Patrón clave: el Stream<NfcTag> en el repositorio permite que el BLoC/Riverpod reaccione en tiempo real a cada tag sin bloquear el UI thread. stopSession() cancela el stream limpiamente en el dispose() del widget, evitando memory leaks.

11 — Código Flutter/Dart

NFC en Dart

Con nfc_manager el flujo completo — verificar, leer NDEF y escribir — se hace con pocas líneas idiomáticas.

  1. 1
    Verificar hardware

    isAvailable() consulta si el chip NFC existe y está activo. Retorna bool sin lanzar excepción.

  2. 2
    Iniciar sesión

    startSession(onDiscovered:) activa el campo RF. El callback recibe cada NfcTag detectada de forma asíncrona.

  3. 3
    Procesar + cerrar

    Ndef.from(tag) extrae la interfaz NDEF. Tras leer, llamar stopSession() desactiva el campo RF y libera recursos.

nfc_reader.dart
// 1. Verificar disponibilidad del hardware NFC
final isAvailable =
    await NfcManager.instance.isAvailable();
if (!isAvailable) {
  showError('NFC desactivado o no disponible');
  return;
}

// 2. Iniciar sesión — activa el campo RF
await NfcManager.instance.startSession(
  onDiscovered: (NfcTag tag) async {

    // 3. Obtener interfaz NDEF del tag
    final ndef = Ndef.from(tag);
    if (ndef == null) return;

    // 4. Leer mensaje y primer registro
    final msg = await ndef.read();
    final payload = msg?.records.first.payload;
    // Saltar los 3 bytes de header NDEF (lang/flags)
    final texto =
      String.fromCharCodes(payload!.skip(3));

    // 5. Escritura NDEF (opcional)
    final newRecord = NdefRecord.createUri(
      Uri.parse('https://unicesar.edu.co'));
    await ndef.write(NdefMessage([newRecord]));

    // 6. Cerrar sesión limpiamente
    await NfcManager.instance.stopSession();
    mostrarEnPantalla(texto);
  },
);

12 — Permisos en Android nativo

Permisos y declaraciones

El NFC es un permiso de instalación, no de ejecución: se declara en el AndroidManifest.xml y no muestra diálogo emergente al usuario.

AndroidManifest.xml
<!-- Solicita acceso al hardware NFC -->
<uses-permission android:name="android.permission.NFC" />

<!-- Exige que el dispositivo tenga chip NFC -->
<uses-feature android:name="android.hardware.nfc"
              android:required="true" />

Sin diálogo runtime

No requiere runtime permission: el usuario lo acepta al instalar. Normal-level permission (sin firma especial).

required="true"

Filtra en Google Play los equipos sin NFC. Usa false si el NFC es opcional en tu app.

Estado en runtime

El usuario puede desactivar el NFC. Verificar con NfcAdapter.isEnabled() antes de cada sesión.

14 — Seguridad

¿Es seguro?

El corto alcance es su primera defensa, pero no la única a considerar.

A favor

Proximidad obligatoria

Interceptar exige estar a centímetros. El usuario debe acercar el equipo de forma deliberada — no hay escucha pasiva posible a distancia.

A favor

Capas cifradas

Pagos y accesos usan tokens efímeros y cifrado AES-128 sobre NFC (PACE/BAC). El número real de la tarjeta nunca viaja en claro.

Riesgo

Etiquetas maliciosas

Una etiqueta puede contener una URL falsa o un payload con código de exploit. La app siempre debe validar y sanitizar el contenido leído.

Riesgo

Relay / escaneo oculto

Ataques relay amplifican el campo. Buenas prácticas: confirmar acciones críticas, bloquear etiquetas en solo lectura y exigir desbloqueo del equipo.

15 — Aplicaciones

El NFC en la vida real

Pagos sin contacto

Google Pay, Apple Pay, transporte público. Token efímero + AES-128.

Control de acceso

Tarjetas MIFARE DESFire en oficinas, hoteles, llaves digitales del auto.

Identificación

DNI, pasaportes ICAO 9303, carnés universitarios con chip BAC/PACE.

Emparejamiento

Un toque para conectar audífonos o parlantes Bluetooth/Wi-Fi vía Android Beam / SNEP.

Posters inteligentes

Etiquetas NDEF tipo SmartPoster que abren webs, menús digitales o descuentos.

Salud y trazabilidad

Pulseras de pacientes, inventario médico RFID+NFC, cadena de frío farmacéutica.

Conclusión

Un campo invisible,
un toque visible

El NFC convierte décadas de física electromagnética y normativa ISO en una experiencia tan simple como acercar dos objetos. Detrás del "tap" hay inducción, ASK, ISO 14443, anticolisión, NDEF y una arquitectura de software limpia y predecible en Flutter.
